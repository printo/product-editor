# ── HEIC/HEIF decoding (iPhone photos) ──────────────────────────────────────
# Bundles a current libheif (1.21.x) as a manylinux wheel — no system packages
# needed. Used by services/heic.py behind POST /api/heic/convert.
#
# Why this exists at all: the browser-side heic2any decoder is a 2021 build of
# libheif and cannot read the format current iPhones produce. An iOS 18 photo
# is a `tmap` derived image (Apple gain-map HDR) whose pixels live in `grid`
# tiles; that decoder does not recognise the primary item and fails outright.
# Chrome and Firefox have no HEIC codec of their own to fall back to, so
# without a server-side decode those photos cannot be used at all.
#
# Pillow and pillow-heif move together (1.3.0 is the release built against Pillow 13).
# Any bump of either needs the before/after render comparison on real photos, HEIC,
# blur, masks, text and PDF that the 2026-11-19 move to Pillow 13 was checked with.
pillow-heif==1.3.0

# handles POST /api/orientation/detect (synchronous, inline). Celery workers
# share the same Dockerfile so they also have it installed but they never
# import the module — the orientation endpoint only runs on backend.
# Pulls in opencv-contrib-python, numpy and matplotlib; Apache 2.0 throughout. 1.x dropped `mp.solutions` and the bundled face model (the face

# 0.10.x held at 4.25. Needs libegl1 in the image. Re-run the cx-sample
# orientation check (docs/HISTORY.md) on any bump.
